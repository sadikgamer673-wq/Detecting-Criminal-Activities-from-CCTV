# AI Model Limitations, CPU Inference, and Ethical Principles

## 1. Ethical Core Principles

### 1.1 Presumption of Innocence
This application is strictly an **incident triage and computer vision assistance tool**. 
- Detections generated by AI models are classified as **Potential Incidents** or **Model Detections**.
- The system **never declares a person guilty of a crime**.
- All detections must undergo human operator review, verification, and audit before any action or report is finalized.

### 1.2 Prohibited Capabilities
In compliance with ethical AI standards:
- **No Facial Recognition**: The system does not attempt facial recognition or biometric identification.
- **No Demographic Profiling**: The system does not predict or infer identity, criminal history, ethnicity, gender, religion, or sensitive personal attributes.

## 2. CPU Inference Realities & Performance Limits

### 2.1 Hardware Considerations on Windows 11
The application is designed to operate on Windows 11 PCs without dedicated NVIDIA GPUs. Running multi-modal computer vision models purely on CPU entails fundamental physical constraints:
- **Full FPS Processing is Impractical on CPU**: Processing high-resolution 1080p or 4K RTSP streams at 30 FPS using dense neural networks on a CPU causes severe frame dropping, thread contention, and thermal throttling.
- **Configurable Subsampling**: The pipeline employs temporal frame subsampling (default: 5 FPS). Consecutive frames are skipped, analyzing keyframes to maintain real-time responsiveness without choking CPU threads.
- **Input Resizing**: Video frames are dynamically resized (e.g., 640x360 or 640x640) prior to inference to minimize tensor operations.

### 2.2 Model Selection Constraints
- **Object Detection**: Lightweight models from the YOLO family (such as YOLOv8n or YOLOv11n) are selected specifically for ONNX / CPU-optimized inference.
- **Temporal Activity Recognition**: Dense 3D spatio-temporal video architectures (e.g., SlowFast, VideoMAE) require significant compute and memory bandwidth. Lightweight temporal windowing models or multi-frame pose/motion aggregation are required for CPU environments.

## 3. Supported Activity Categories vs. Future Roadmap

| Category | Initial Status | Technical Method | Limitations on CPU |
| :--- | :--- | :--- | :--- |
| **Person Detection & Tracking** | **Supported** | YOLOv8n / YOLOv11n + ByteTrack | High accuracy for bounding boxes; occlusions in dense crowds can degrade tracking IDs. |
| **Restricted Area Entry** | **Supported** | Geometric polygon intersection | Highly reliable; depends on camera angle calibration. |
| **Unusual Movement Patterns** | **Supported** | Optical flow / Motion vector delta | Detects sudden sprints, falls, or erratic paths; sensitive to camera vibration. |
| **Physical Violence / Fighting** | **Phase 2 Validation** | Temporal pose / interaction network | High false positive rate with hugging, sports, or rapid gestures; requires human review. |
| **Weapon Recognition** | **Phase 2 Validation** | Specialized fine-tuned detector | Small object size and perspective distortion make knife/gun detection error-prone without high-res optics. |
| **Theft & Vandalism** | **Future Scope** | Multi-step temporal reasoning | Extremely context-dependent; cannot be substituted with naive motion thresholds. |

## 4. False Positive Mitigation

1. **Multi-Frame Temporal Confirmation**: A detection is not triggered by a single transient anomalous frame; activity must persist across a minimum temporal window (e.g., 1.5 to 3 seconds).
2. **Event Cooldown Window**: Once an incident is triggered, identical detections within a configurable cooldown window (e.g., 10 seconds) are merged into the existing event rather than generating duplicate alerts.
3. **Audit Lifecycle**:
   - `Potential Incident` (Model prediction)
   - `Acknowledged` (Operator alerted)
   - `Human-Reviewed` (Operator verified)
   - `Dismissed False Positive` (Recorded for model evaluation and retraining)
